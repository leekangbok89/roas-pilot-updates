        미리보기 · 파일명분석 이름

        구간별 수치는 맨 위 성과표에서 확인하세요. 긴 이미지의 여러 구간은 서로 다른 분석 영역이며 고유 방문자로 합산하지 않습니다.

        이름은 상품번호·상세 버전별로 이 PC에 저장됩니다. 이미지 미리보기는 분할 구간이 아닌 원본 전체입니다. 콘텐츠 순서·파일을 바꾸면 상세 버전과 자사몰 설치코드도 함께 바꿔 새 목록을 불러오세요. 처음 불러온 목록은 현재 페이지 기준이므로 그 이전에 페이지 구성이 달랐다면 과거 통계와 대조가 필요합니다.

        설치 · 연동 설정

        설정 저장은 자사몰에 코드를 설치하지 않습니다. 아래 코드를 카페24 PC·모바일 상품 상세 스킨에 각각 한 번 적용해야 수집이 시작됩니다.

        확장 추적 · 구매 연결 · A/B 설정

        카페24 공통 영역과 주문 완료 레이아웃에 생성 코드를 각각 한 번 설치하세요. 이미 수신되는 GA4 add_to_cart·begin_checkout·purchase 이벤트에서 같은 상품 ID를 확인할 때 연결합니다. 결제 이벤트가 없으면 수집됐다고 표시하지 않습니다. 주문번호는 원문 대신 해시로만 전송해 이 PC의 카페24 주문과 대조합니다.

        A/B는 기존 상세(A) 외에 <template id="roas-detail-b">B 상세 HTML</template>을 실제 페이지에 추가하고 서로 다른 B 버전과 실험 ID를 설정해야 동작합니다. B 콘텐츠가 없으면 배정하지 않습니다. 브라우저별 50:50 배정을 유지하며 과거·현재 버전을 단순 비교한 자료를 무작위 실험으로 표시하지 않습니다.

        GA4 측정 ID는 현재 자사몰에서 확인된 값입니다. 기존 GA4 연결 속성이 이 웹 스트림을 포함하는지 확인하세요. 상세 구성이 바뀌면 버전을 v2, v3처럼 바꾸고 설치코드도 교체하세요.

        설치할 상세페이지 열기 ↗
        1. 카페24 디자인 편집에서 실제 사용 중인 PC·모바일 공통 영역과 주문 완료 레이아웃에서 기존 ROAS 추적 블록을 새 코드로 교체하세요. 이미 공통 영역이 포함되는 템플릿에는 중복 추가하지 마세요. 기존 Google 태그는 유지합니다. 공통 레이아웃에 넣어도 위마망의 지정 상품에서만 동작합니다.
        2. Clarity 설정 → 설치 → 수동 설치의 clarity.ms/tag/ 뒤 값이 프로젝트 ID입니다. Clarity가 이미 설치되어 있으면 기존 프로젝트 ID를 사용하세요.
        3. GA4 관리자 → 데이터 표시 → 맞춤 정의에서 아래 4개 측정기준과 1개 측정항목을 등록하세요. 범위는 모두 이벤트입니다.
        4. 설치 후 GA4 실시간·DebugView에서 rp_detail_view, rp_content_view, rp3_detail_view 수신을 확인하세요. 구매 연결은 주문 완료 페이지의 기존 purchase 이벤트 또는 ROAS_DETAIL.trackEcommerce("purchase", 기존_결제완료_이벤트_객체) 호출이 필요합니다. 실제 결제가 확인된 데이터만 전달하고 구매 버튼 클릭에 이 함수를 연결하지 마세요. 이 화면의 일반 보고서 반영에는 24~48시간이 걸릴 수 있습니다.
