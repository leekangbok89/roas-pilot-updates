## 상세페이지 분석

### 콘텐츠 미리보기와 이름 저장

영상은 자동 재생창 대신 영상의 약 1초 장면(짧은 영상은 길이의 1/3)을 추출한 썸네일로 표시합니다. 접근 가능한 영상은 JPEG를 이 PC의 버전별 콘텐츠 목록에 저장해 다시 표시합니다. CORS 때문에 JPEG 저장이 제한돼도 읽을 수 있는 장면은 캔버스로 표시합니다. 영상 서버가 재생 자체를 차단하면 ‘썸네일 등록 / 변경’에서 이미지 또는 원본 영상 파일을 선택해 등록할 수 있습니다. 파일은 브라우저에서 최대 320×240 JPEG로 변환한 썸네일만 저장하며 원본 파일은 업로드하지 않습니다. 이름을 편집 중이어도 썸네일 저장이 입력값을 초기화하지 않습니다. 썸네일 클릭은 원본 영상 열기입니다.

업데이트 후 **이미지 · 영상 이름 관리 → 자사몰 콘텐츠 불러오기**를 누르면 현재 백도씨 페이지의 이미지·영상 파일을 순서 ID와 연결합니다. 이미지 썸네일과 영상 재생 컨트롤, 원본 열기, 파일명이 표시됩니다. 직접 이름을 붙인 뒤 **이름 저장**을 누르면 같은 이름과 파일명이 GA4 통계 표에도 표시됩니다. 기존 추적 코드와 이벤트 매개변수를 그대로 사용합니다.

목록과 이름은 이 PC의 `.roas-private/detail-catalog.json`에 상품번호·상세 버전별로 저장됩니다. 같은 버전에서 순서나 파일 URL이 달라지면 다시 불러오기를 거부해 기존 통계의 콘텐츠 연결을 보존합니다. 파일 내용만 같은 URL에 덮어쓰는 변경은 감지할 수 없으므로 콘텐츠 변경 시 버전과 자사몰 설치코드를 함께 변경해야 합니다. 첫 목록은 현재 페이지 기준이며 과거 구성이 달랐다면 당시 통계와 별도 대조가 필요합니다. 분할 이미지의 썸네일은 원본 전체이며 구간 번호를 함께 표시합니다. GIF도 원본 이미지로 표시됩니다.

**상세페이지 분석** 메뉴는 위마망 상품 458의 콘텐츠 도달·화면 체류·영상 재생 분량을 기존 GA4 읽기 전용 연결로 조회합니다. Clarity 히트맵·녹화는 프로젝트 화면 링크로 연결합니다. Clarity Export API는 사진별 히트맵을 제공하지 않으며 이 기능에서 호출하지 않습니다.

1. **설치 · 연동 설정**에서 현재 측정 ID `G-RZF6S41CF0`와 선택한 Clarity 프로젝트 ID를 저장합니다. GA4 연결 속성에 해당 웹 스트림이 포함되는지 확인합니다.
2. 생성 코드를 카페24의 사용 중인 PC·모바일 상품 상세 스킨에 각각 한 번 설치합니다. 공통 레이아웃에 넣어도 `wemamang.com`, `www.wemamang.com`, `m.wemamang.com`의 지정 상품에서만 동작합니다. 기존 Google 태그·동의 설정을 유지합니다. 동의 관리 도구를 쓰면 해당 설정과 수집 시작/철회 신호를 연결해야 합니다.
3. GA4 **맞춤 정의**에서 `rp_product_id`, `rp_content_version`, `rp_content_id`, `rp_content_type`을 이벤트 범위의 맞춤 측정기준으로, `rp_visible_ms`를 이벤트 범위의 맞춤 측정항목(밀리초)으로 등록합니다.
4. GA4 실시간 또는 DebugView로 `rp_detail_view`, `rp_content_view` 수신을 확인합니다. 일반 보고서와 맞춤 정의 반영은 24~48시간이 걸릴 수 있습니다.

도달은 해당 구간의 절반 이상(뷰포트보다 긴 구간은 뷰포트 절반 이상)이 보인 시간이 누적 1초 이상인 페이지 조회입니다. 이미지는 원본 높이 1,000px 기준으로 최대 50구간으로 나누며 이미지 로딩 후 추적합니다. 체류는 숨겨진 탭과 화면 밖 시간을 제외한 구간별 시간입니다. 도달률의 분모는 추적 페이지 조회이며 사용자 수가 아닙니다. 여러 구간이 동시에 보일 수 있어 체류시간을 합쳐 페이지 전체 시간을 계산하지 않습니다.

MP4·YouTube 재생률은 화면에 보이는 동안 실제 재생한 고유 분량을 기준으로 25/50/75/100%를 기록하고, 98% 이상을 완료로 봅니다. 탐색 이동만으로 완료 처리하지 않습니다. YouTube iframe은 저장된 주소에 `enablejsapi=1`이 필요합니다. GIF는 이미지로 집계합니다. **구매/장바구니 버튼 클릭**은 페이지 조회당 1회이며 실제 결제 성공이나 구매 기여를 뜻하지 않습니다.

상세 구성이 달라지면 **상세페이지 버전**을 변경하고 사이트 설치코드도 교체합니다. 설치 전 데이터는 소급되지 않습니다. GA4 보고서는 선택 상품·버전·기간으로 격리하며 5분 캐시와 최대 93일 제한을 사용합니다. 인증정보는 기존 DPAPI 저장소를 공유하고 설치코드에는 포함하지 않습니다.

```sh
node scripts/bundle-ga4.cjs
node scripts/bundle-shell.cjs
npm test
ROAS_PLAYWRIGHT_MODULE=/path/to/playwright node scripts/smoke-detail-browser.cjs
```

## 네이버 검색광고 API

왼쪽 **검색광고 분석** 메뉴에서 검색광고 계정을 연결합니다. **설정 관리 → 계정 연결**에도 연결 화면 바로가기가 있습니다.

1. 네이버 광고주센터 → **검색광고 → 도구 → SA API 사용 관리**에서 API 서비스를 신청합니다.
2. 해당 화면의 **고객 ID(Customer ID)**, **액세스라이선스(API Key)**, **비밀키(Secret Key)**를 ROAS Pilot 화면에 입력합니다. 스마트스토어 커머스API 키와 별도입니다.
3. **연결 확인 후 암호화 저장**을 누르면 캠페인 목록으로 인증을 검사한 뒤 저장합니다. 이어서 **집계할 위마망 캠페인 선택**에서 해당 캠페인만 체크하고 저장하면 최근 7일을 조회합니다. 인증 실패 시 이전 연결을 유지합니다.

고객 ID·키는 로컬 `http://127.0.0.1:3000/naver-search.html` 화면에서만 입력하며 채팅·GitHub에 올리지 않습니다. 키는 Windows DPAPI로 `.roas-private/naver-search.dpapi`에 암호화 저장합니다. 외부 네이버 API에는 GET 조회만 요청하고 예산·입찰·ON/OFF를 변경하지 않습니다.

- 위마망 캠페인을 사용자가 선택하고 저장하기 전에는 계정 전체 보고서와 자동 수집을 중지합니다. 선택은 고객 ID별로 서버에 저장하며 새 캠페인을 자동 포함하지 않습니다. 한 캠페인에 여러 브랜드가 섞이면 광고 운영 구조에서 분리한 뒤 선택해야 합니다.
- 캐시는 선택한 캠페인 ID 조합별로 격리합니다. 기존 전체 계정 캐시와 다른 선택의 합계를 재사용하지 않습니다. 구매·일별 합계와 자동 수집에도 같은 선택을 적용합니다.
- 캠페인별/일별 광고비·노출·클릭·CTR·CPC·CPM·구매완료 수·구매완료 매출·구매 ROAS를 표시합니다. 광고비 `salesAmt`는 VAT 포함 원화이며, 구매는 `purchaseCcnt`, `purchaseConvAmt`로만 계산합니다. 전체 전환 수/가치를 구매로 대체하지 않습니다.
- **최근 7일 매시간 자동 갱신**은 기본으로 켜집니다. 서버 실행 시 점검하고 이후 매분 갱신 시점을 확인합니다. 해당 연결의 최근 7일을 마지막 시도 후 1시간마다 수집합니다. 브라우저를 닫아도 서버가 실행 중이면 수집하며 PC 절전/종료 중에는 수집하지 않습니다.
- 기간 조회는 한 번에 최대 31일입니다. 같은 기간의 저장 자료는 5분간 재사용하며 **새로 가져오기**는 API로 다시 조회합니다. 모든 캠페인 조회 성공 후 파일을 교체합니다. 갱신 실패 시 이전 자료·원래 수집 시각·실패 이유를 표시합니다.
- 지원되는 캠페인 목록에 반환된 항목만 조회합니다. 삭제된 캠페인은 누락될 수 있으며 미응답/누락 구매 지표는 미확인으로 표시합니다. 일부 캠페인의 일별 성과가 없으면 일별 합계도 확정하지 않습니다. 최근 전환 값은 이후 수정될 수 있습니다.
- 선택한 위마망 캠페인은 검색광고 분석 → 캠페인별 성과 · 광고비 연결에서 광고비 반영 항목(자동·네이버 쇼핑검색·네이버 파워링크·GFA·합계에서 제외)을 선택하고 저장할 수 있습니다. 저장한 연결은 과거·향후 수집 자료의 한눈에 보기·공통 광고비·이익에 적용하며 캠페인 성과 자체는 유지합니다. 기본 자동 분류는 SHOPPING→쇼핑검색, WEB_SITE→파워링크입니다. 같은 날짜·항목은 API 수집값을 우선하여 수동 입력과 중복 합산하지 않습니다. API 연결이 없는 GFA는 저장한 수동 광고비를 반영하며 검색광고 구매매출을 쇼핑몰 매출에 더하지 않습니다. 기존 혼합 캠페인 캐시는 검색광고 화면의 “새로 가져오기”를 한 번 실행하면 일별로 구분됩니다. 연결 해제는 검색광고 인증정보를 삭제하고 자동 수집을 끄며, 다른 연결과 저장된 성과는 유지합니다.

수정 후 `node scripts/bundle-naver-search.cjs`로 서버에 클라이언트와 화면을 포함합니다. 기존 업데이트 프로그램이 새 파일을 복사하지 못해도 포함된 화면으로 실행됩니다. 검증: `node scripts/bundle-naver-search.cjs --check`, `npm test`, `node scripts/smoke-naver-search-browser.cjs`.

공식 근거: [키 발급 안내](https://ads.naver.com/help/faq/991), [API 명세](https://naver.github.io/searchad-apidoc/), [구매 지표 추가 공지](https://github.com/naver/searchad-apidoc/blob/gh-pages/_posts/2026-03-20-notice1.md).

## GA4 유입 분석

왼쪽 메뉴의 **GA4 유입 분석**에서 자사몰의 방문, 참여율, 광고 UTM과 방문 시작 페이지를 확인합니다.

### 처음 연결하기

1. Google Cloud 프로젝트에서 **Google Analytics Data API**를 사용 설정합니다.
2. 서비스 계정을 만들고, 그 이메일을 GA4 속성의 **뷰어**로 추가합니다. 구매매출을 조회하려면 수익 지표 접근 제한이 없어야 합니다.
3. 서비스 계정의 JSON 키를 내려받아 보관합니다.
4. ROAS Pilot → **GA4 유입 분석**에서 숫자형 **속성 ID**와 JSON 파일을 선택하고 **연결 확인 후 저장**을 누릅니다. 위마망 속성 ID는 `560644825`입니다.

`G-`로 시작하는 측정 ID는 이 연결에 사용하지 않습니다. 인증파일은 채팅이나 GitHub에 올릴 필요가 없습니다. Windows PC에서 실행 중인 `http://localhost:3000` 또는 `http://127.0.0.1:3000` 화면에서 등록합니다.

### 데이터 읽기

- **전체 유입 / Meta 유료 유입**을 선택할 수 있습니다. 한 번에 최대 93일이며, 같은 조회는 서버 메모리에 5분간 보관합니다. **새로 가져오기**는 이 캐시를 갱신합니다.
- 광고 UTM의 `utm_content`에 Meta 광고 ID를 넣으면, 선택 기간에 이 PC에 저장된 Meta 광고 기록의 이름과 연결합니다. 아직 저장하지 않은 광고는 원본 UTM을 표시합니다.
- 요약의 사용자 수·비율·평균은 별도 GA4 합계 조회 결과입니다. 여러 광고를 방문한 사용자가 중복될 수 있어 표의 사용자 수를 더하지 않습니다.
- 평균 세션 시간은 방문 전체의 시간입니다. 상세페이지의 특정 영역을 실제로 읽은 시간을 뜻하지 않습니다.
- 구매 이벤트 수신 검사는 **선택 기간의 속성 전체** 기준입니다. 수신이 확인되지 않으면 구매·매출을 **미확인**으로 표시합니다. 이벤트가 수신되어도 주문 누락·중복·금액 정확성은 주문 데이터와 대조해야 합니다.
- GA4 구매매출, Meta 광고 귀속 매출, 쇼핑몰 주문매출은 각각의 기준으로 표시합니다. 기존 매출·이익 계산에 GA4 매출을 더하지 않습니다.
- 표는 세션 수 기준 최대 5,000행을 받으며, 전체 행 수가 더 크거나 GA4가 표본·기준점·데이터 제한을 알려주면 보고서에 표시합니다.

새로 설치한 태그의 일반 보고서 반영에는 24~48시간이 걸릴 수 있습니다. 설치 이전 방문은 소급 수집되지 않습니다. Google 공식 안내: [데이터 최신성](https://support.google.com/analytics/answer/11198161?hl=ko), [Data API 시작하기](https://developers.google.com/analytics/devguides/reporting/data/v1/quickstart), [지표·차원 정의](https://developers.google.com/analytics/devguides/reporting/data/v1/api-schema).

### 인증정보와 업데이트

서비스 계정 키는 Windows DPAPI의 현재 사용자 범위로 암호화해 `.roas-private/ga4.dpapi`에 저장합니다. 원본 JSON이나 액세스 토큰을 브라우저 저장소·로그·배포물에 기록하지 않습니다. Google 읽기 전용 권한으로만 보고서를 요청하며, 연결 검사가 성공한 뒤 새 설정을 저장합니다. 실패하면 기존 설정을 유지합니다. **연결 해제**는 이 PC의 저장된 GA4 설정을 삭제하며 Google의 서비스 계정 키 자체를 폐기하지는 않습니다.

기존 버전의 업데이트 프로그램이 새 파일을 복사하지 못하는 경우를 위해 GA4 실행 코드와 화면을 `server.js`에도 포함합니다. 수정 후 다음 생성·검증을 실행합니다.

```sh
node scripts/bundle-shell.cjs
node scripts/bundle-ga4.cjs
node scripts/bundle-shell.cjs --check
node scripts/bundle-ga4.cjs --check
```

## 셀하 모드 (v2.8.169)

기존 네이버 분석 화면 위쪽의 **셀하 모드** 버튼으로 쿠팡 전용 화면을 엽니다. 상단의 **기존 네이버 모드로** 버튼으로 돌아옵니다. 상품 리스트·그룹 관리·대시보드·매출 분석·광고 분석·자료 연결은 쿠팡 전용 경로와 기존 쿠팡 API를 사용합니다. 네이버·Meta 자료를 합산하거나 연결·원가·상품 집계 범위를 변경하지 않습니다. 기존 네이버 테마는 보존하고 셀하 모드는 독립된 밝은 화면으로 표시합니다.

셀하의 로그인 후 실제 화면을 참고해 상단 가로 메뉴, 노란 선택 밑줄, 그래프와 일일 보고서의 2열 배치, 하단 상품별 일일 표를 구성했습니다. 기간 합계·자동 저장 상태와 빠른 기간 선택은 접은 영역에서 확인합니다. 데이터 수집과 원가·손익 계산은 기존 구현을 사용하며, 셀하 서비스의 미구현 기능을 제공하는 것처럼 표시하지 않습니다.

검증: `npm test`, `node scripts/bundle-shell.cjs --check`, `node scripts/bundle-coupang.cjs --check`, `node scripts/smoke-growth-mode.cjs`, `node scripts/smoke-coupang-daily-report.cjs`. 브라우저 검사는 `ROAS_PLAYWRIGHT_MODULE`과 필요 시 `BROWSER_EXECUTABLE`을 지정합니다. 구형 업데이트의 누락 파일과 남아 있는 이전 스타일도 검사합니다.

## 일간 모니터링 (v2.8.170)

셀하 모드 → **모니터링**에서 네이버·쿠팡 상품을 카드로 확인하고, 상품을 열어 키워드 순위·리뷰·판매량 기록을 봅니다. 검색, 폴더, 관심 상품, 순서 변경, 보관·복원, 크게보기, 순위표 가로·세로 전환과 표시 항목 설정을 지원합니다. 기존 매출·광고 자료와 분리된 `.roas-data/daily-monitoring/state.json`에 저장합니다.

**자료 가져오기**는 전체 JSON 백업(최대 160MiB), CSV·TSV·XLSX(최대 8MiB)를 지원합니다. 상품 상세에서 가져오면 해당 상품에 연결할 수 있습니다. 날짜는 `YYYY-MM-DD`, 숫자형 순위 또는 `80위 밖`·`업데이트 중`·`-`를 사용합니다. 키워드별 날짜가 가로로 있는 표는 전체 날짜 또는 파일명에 명시된 연도가 필요합니다. 실제 수집된 페이지·페이지 내 순위·범위 기준만 표시하며 누락 값은 0으로 바꾸지 않습니다.

현재 화면은 가져온 관측 기록을 표시합니다. 셀하·네이버·쿠팡의 순위를 매일 자동 수집하거나 외부 순위 알림을 발송하지 않습니다. **순위 알림** 설정은 저장된 순위가 기준을 벗어난 키워드를 화면에서 강조합니다. 리뷰·판매량도 가져온 기록에 있는 값만 표시합니다. **전체 자료 내보내기**로 양쪽 플랫폼·보관 상품·폴더·설정·과거 기록을 함께 백업할 수 있습니다.

검증: `npm test`, `node scripts/bundle-monitoring.cjs --check`, `node scripts/bundle-shell.cjs --check`. 모니터링 서비스와 화면을 수정한 뒤 `node scripts/bundle-monitoring.cjs`로 구형 업데이트에서도 사용하는 서버 내장본을 갱신합니다.
