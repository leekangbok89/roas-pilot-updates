# 쿠팡 수익 분석 초안

`/coupang.html`에서 로켓그로스를 기본으로 조회하고 판매자배송과 전체를 선택할 수 있습니다. 업체코드 및 키를 Windows DPAPI로 저장한 뒤 각 배송 방식의 주문 수집 버튼으로 연결을 확인합니다. 자료는 `.roas-data/coupang/{vendorId}`에 보관하며 업데이트 대상에 포함하지 않습니다.

주문을 수집한 후 위마망 옵션만 체크해 저장합니다. 트루버 등 미선택 상품은 집계하지 않습니다. `vendorItemId` 기준으로 선택하며 주문 수집 전 직접 추가할 수도 있습니다. 선택 집합별로 비용 장부를 분리합니다.

## 제공 범위

- 로켓그로스: 공식 주문 API의 결제일별 주문. 출고 후 주문만 반환합니다.
- 판매자배송: 일단위 발주서 API의 6개 상태를 순회하며 주문일별 조회. 반품 완료 주문은 포함되지 않을 수 있습니다.
- 수집은 요청당 최대 7일, 조회는 최대 366일. 저장 자료 조회는 외부 API를 호출하지 않습니다.
- 원가는 상품별 개당 도착원가를 등록하고 수량 기준 초안을 계산합니다. 원가가 없으면 미확인으로 둡니다.
- 광고비, 그로스 입출고비·보관비·배송비·반품비와 환불 반영 매출 등은 일별 합계로 입력·확인합니다. 현재 이 비용의 자동 수집, 쿠팡 광고 API, 정산 API 대사, 보고서 업로드, 자동 주기 갱신은 구현하지 않았습니다.

## 계산 기준

예상 이익 = 환불·할인 반영 매출 - 상품원가 - 수수료 - 광고비 - 입출고/입고운송비 - 배송비 - 보관비 - 반품비 - 기타 비용.

필수 항목을 모두 입력하고 사용자가 반품·비용을 확인해야 날짜별 이익이 계산됩니다. 없는 비용은 0을 명시합니다. 환불만 발생한 날의 음수 매출을 허용합니다. 기간 내 미확인 날짜가 있으면 기간 전체 이익을 표시하지 않습니다. API 주문 자료가 바뀌면 기존 확인을 무효로 하고 재확인을 요구합니다. 원가 입력값이 바뀌어도 이미 확인한 과거 비용 장부는 바꾸지 않습니다.

입력 비용 범위의 부가세 포함 현금 기준 예상 이익이며 회계상 당기순이익이나 최종 정산금이 아닙니다. 상품별 이익 배분은 하지 않습니다. API 주문 합계에는 환불/할인/배송 정산 차이가 있을 수 있으므로 매출 확인값과 구분합니다.

## 검증 및 배포

`node --test tests/coupang.test.js`로 서명, 페이지 수집, 브랜드 분리, 비용 누락, 재수집 무효화, 계정 분리 등을 검증합니다. `node scripts/bundle-coupang.cjs`로 런타임과 화면을 server.js에 포함해 신규 파일을 모르는 구버전 업데이터에서도 화면과 서버가 함께 작동하게 합니다. 실제 계정 API 연결 및 WING 정산 대사는 API 키를 등록한 뒤 확인해야 합니다.
