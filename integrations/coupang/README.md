# 쿠팡 수익 분석

## API 수집과 저장 자료 계산

프로그램 실행 후 연결과 집계 상품이 등록돼 있으면 최근 7일 주문을 날짜·배송 방식별로 저장합니다. 이후 서버가 켜져 있는 동안 1시간마다 다시 확인하며, 1년 전체 수집이 완료되지 않아도 시작합니다. 대시보드의 **API 최근 7일 수집·저장**으로 즉시 실행할 수도 있습니다. 화면을 닫아도 서버 수집은 계속되고, **저장 자료 조회**는 외부 API를 다시 호출하지 않습니다.

API 예상 이익은 저장된 주문금액에서 상품별 등록 원가·수수료율·입출고비·배송비로 계산한 예상 비용을 차감합니다. 등록 비용 변경은 저장 주문에 즉시 재적용하며 원가 적용일과 미등록 항목을 확인합니다. 주문·원가·비용은 `.roas-data/coupang/{vendorId}`에 보존하며 고객 연락처·주소는 저장하지 않습니다.

예상 이익은 광고비 차감 전입니다. 주문 API의 반품·정산·광고비가 확정된 최종 순이익으로 표시하지 않습니다. 셀하 파일 또는 확인한 비용 장부의 원본 손익은 별도 우선순위를 유지합니다. 채널별 수집 실패 시 이전 자료를 보존하고 마지막 저장 범위·시각·오류를 표시합니다. 실패한 조회도 1시간 간격을 유지하며 수집 버튼으로 다시 실행할 수 있습니다. 기존 장기 수집 진행 기록은 최근 7일 갱신과 별도로 유지합니다.

공식 문서: [주문 조회](https://developers.coupang.com/ko/api/shipments/po-list-query-paging-by-day?market=KR), [로켓그로스 주문](https://developers.coupang.com/ko/api/rocket-growth/rg-order-apilist-query?market=KR), [매출·정산 인식일](https://developers.coupang.com/ko/api/settlement/sales-detail-query?market=KR).

## 손익 결과와 같은 수치로 집계

대시보드 또는 상품별 매출·손익 화면의 **셀하 손익 엑셀 가져오기**에서 하루 단위 XLSX를 최대 31개 함께 선택할 수 있습니다. `roas-coupang-sales-v1` 형식의 설정 JSON 한 파일도 같은 경로로 읽습니다. 날짜별·전체 미리보기를 확인하고 저장하면 같은 날짜 자료를 교체합니다. 상품 합계행을 제외한 옵션행만 합산하며 주문 API 매출과 더하지 않습니다.

**파일의 모든 옵션을 쿠팡 집계에 포함**을 선택하면 누락된 옵션을 추가하고 기존 원가·수수료 설정을 유지합니다. 이 설정은 쿠팡 분석에만 적용합니다. 반품의 음수 수량·금액, 음수 일반 판매량, 판매 없이 발생한 광고비도 원본대로 보존합니다.

계산은 `셀하 순이익 = 이익금 − 광고 집행비`, `광고 집행 순이익 = 광고 집행 이익금 − 광고 집행비`, `광고 외 비용 합계 = 할인 후 매출 − 이익금`입니다. 광고 외 비용 합계는 원가·수수료·물류비 등을 분리한 값이 아닙니다. 광고 이익은 원본값을 사용하여 반올림 오차를 피합니다. 광고 ROAS는 광고 매출/광고비, 광고 집행 순이익률은 광고 순이익/광고비이며 광고비가 0이면 비율을 표시하지 않습니다.

신규고객확보 광고비는 파일에 없으면 미확인으로 유지합니다. 여러 날짜에 같은 금액을 자동 복제하지 않으며 셀하 순이익에서 임의 차감하지 않습니다. 전체 광고비 반영 순이익은 해당 날짜·배송 방식의 추가 광고비를 확인한 뒤 계산합니다.

`/coupang.html`에서 로켓그로스를 기본으로 조회하고 판매자배송과 전체를 선택할 수 있습니다. 업체코드 및 키를 Windows DPAPI로 저장한 뒤 각 배송 방식의 주문 수집 버튼으로 연결을 확인합니다. 자료는 `.roas-data/coupang/{vendorId}`에 보관하며 업데이트 대상에 포함하지 않습니다.

쿠팡 수익 분석은 트루버와 위마망을 함께 분석합니다. 주문을 수집한 후 두 브랜드의 옵션을 체크해 저장합니다. 상품이 많으면 전체 선택 버튼을 사용할 수 있으며, 미선택 상품은 집계하지 않습니다. 다른 메뉴의 위마망 전용 집계에는 영향을 주지 않습니다. `vendorItemId` 기준으로 선택하며 주문 수집 전 직접 추가할 수도 있습니다. 선택 집합별로 비용 장부를 분리합니다.

## 제공 범위

- 로켓그로스: 공식 주문 API의 결제일별 주문. 출고 후 주문만 반환합니다.
- 판매자배송: 일단위 발주서 API의 6개 상태를 순회하며 주문일별 조회. 반품 완료 주문은 포함되지 않을 수 있습니다.
- 조회는 최대 366일. 7일 이하의 주문 API 수집은 바로 실행하고, 장기 수집은 서버의 백그라운드 작업으로 7일 구간마다 페이지를 모두 가져온 뒤 날짜별 파일로 저장합니다. 저장 자료 조회는 외부 API를 호출하지 않습니다.
- 원가는 상품별 개당 도착원가를 등록하고 수량 기준 초안을 계산합니다. 원가가 없으면 미확인으로 둡니다.
- 광고비, 그로스 입출고비·보관비·배송비·반품비와 환불 반영 매출 등은 일별 합계로 입력·확인합니다. 현재 이 비용의 자동 수집, 쿠팡 광고 API, 정산 API 대사, 보고서 업로드, 자동 주기 갱신은 구현하지 않았습니다.

## 최근 1년 저장

‘최근 1년 전체 수집’은 어제까지 최근 365일을 로켓그로스·판매자배송 순서로 수집합니다. 작업은 즉시 응답하고 브라우저가 닫혀도 로컬 서버에서 계속됩니다. 프로그램 자체는 실행 중이어야 합니다. 일시정지는 현재 구간을 저장한 후 적용됩니다. 오류 또는 서버 재시작 후 ‘이어서 수집’으로 완료 구간을 건너뜁니다. 작업 정보는 판매자별 history.json에 보존하고 키를 기록하지 않습니다.

기존 과거 날짜 파일은 재사용하되 최근 7일은 출고 후 주문 반영을 위해 갱신합니다. 완료한 날짜는 주문이 없는 경우에도 확인된 빈 파일로 저장합니다. 실패한 구간은 빈 날짜로 덮어쓰지 않습니다. 저장 자료를 자동 삭제하지 않으므로 업데이트 후에도 최소 1년 자료가 유지됩니다. 과거 API 데이터의 실제 제공 범위는 쿠팡 응답에 따릅니다. 429/5xx/일시적인 네트워크 오류는 최대 3회 재시도하며 인증 오류는 즉시 중단합니다.

판매자배송의 숫자형 금액과 국제화된 KRW Money 객체(currencyCode/units/nanos)를 모두 읽습니다.

최초 1년 수집이 완료된 배송 방식은 backfill.json에 기록합니다. 이후 프로그램 실행 시 한 번, 한국 시간 오늘을 포함한 최근 7일만 자동 재수집합니다. 과거 자료는 유지합니다. 일시정지·실패 등 미완료 수동 수집이 있으면 그 작업을 덮어쓰지 않습니다. 자동 갱신 실패 시 기존 파일을 유지하고 진행 화면에 오류를 표시합니다. 새로 실행할 때 다시 시도하며 같은 실행 중에는 반복 예약하지 않습니다.

## 계산 기준

예상 이익 = 환불·할인 반영 매출 - 상품원가 - 수수료 - 광고비 - 입출고/입고운송비 - 배송비 - 보관비 - 반품비 - 기타 비용.

필수 항목을 모두 입력하고 사용자가 반품·비용을 확인해야 날짜별 이익이 계산됩니다. 없는 비용은 0을 명시합니다. 환불만 발생한 날의 음수 매출을 허용합니다. 기간 내 미확인 날짜가 있으면 기간 전체 이익을 표시하지 않습니다. API 주문 자료가 바뀌면 기존 확인을 무효로 하고 재확인을 요구합니다. 원가 입력값이 바뀌어도 이미 확인한 과거 비용 장부는 바꾸지 않습니다.

입력 비용 범위의 부가세 포함 현금 기준 예상 이익이며 회계상 당기순이익이나 최종 정산금이 아닙니다. 상품별 이익 배분은 하지 않습니다. API 주문 합계에는 환불/할인/배송 정산 차이가 있을 수 있으므로 매출 확인값과 구분합니다.

## 검증 및 배포

`node --test tests/coupang.test.js`로 서명, 페이지 수집, 브랜드 분리, 비용 누락, 재수집 무효화, 계정 분리 등을 검증합니다. `node scripts/bundle-coupang.cjs`로 런타임과 화면을 server.js에 포함해 신규 파일을 모르는 구버전 업데이터에서도 화면과 서버가 함께 작동하게 합니다. 실제 계정 API 연결 및 WING 정산 대사는 API 키를 등록한 뒤 확인해야 합니다.
